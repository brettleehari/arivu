## 1. The problem, in the user's words

> "I have the app, but it wants data. My bundle is finished by the 20th."
>
> "I want help to write this letter properly, and to understand this document
> they sent me. I don't want to pay in dollars for it."
>
> "I don't know where my words go when I type them into these AI things."

*(Hypothesised. Tagged `H` until replaced with sourced quotes.)*

## 2. The specific user

**Amaka, 34, secondary-school English teacher, Enugu.** Tecno Spark-class phone,
4GB RAM, 64GB storage, prepaid data she rations by the week. She writes lesson
notes, parent letters, and forms for the school office. She reads circulars and
contracts she has to understand the same day. She installs apps from Play when
she has Wi-Fi at school and uses them offline at home.

Same shape of user in Jakarta, Manila, Recife, Lima: a capable adult with a
mid-range phone, text to write or understand, and data that costs real money.

## 3. Solution direction (not a spec)

An **offline writing and comprehension assistant**. Not an offline oracle.

A small model bundled inside the app, running on the phone, operating on text
the user gives it: rewrite, shorten, explain, summarise, translate-ish, draft.
One screen. Nothing to configure. The app says plainly what it is bad at
(facts, news, maths, anything it would have to *remember*).

## 4. Commitments (traceability anchors)

Every Leaf item, every feature, every test must map to one of these IDs.
Anything that maps to none is scope creep or a missing Spine update.

| ID | Commitment |
|---|---|
| **C1** | One tap to install from Google Play, then it works. No account, no setup, no model download, no configuration. |
| **C2** | Runs well on a 4GB-RAM Android phone with no internet, ever. |
| **C3** | Verifiably private: no `INTERNET` permission; declares no data collection or sharing. |
| **C4** | Forkable: permissive licences throughout, including model weights; licences visible in-app. |
| **C5** | Honest about what it is: good at the user's text, bad at open-domain recall. Said in-app. |
| **C6** | Will not pretend to work on a phone it cannot serve well: it tells the user and helps them uninstall. |
| **C7** | Never silently forgets: when the conversation exceeds what the model can see, the user is shown. |
| **C8** | Opinionated: no model picker, no parameters, no settings. Every setting is a decision already made. |
| **C9** | Store-compliant: in-app way to report offensive output without network; precise data-safety form. |
| **C10** | Stops when told: generation can be stopped at any token, and survives a brief app switch. |

## 5. Success metrics

| ID | Metric | Target | Measured by |
|---|---|---|---|
| **M1** | Install → first reply, airplane mode, on the test phone | No screen other than chat; ≤ 15s from first send to first token (cold) | Manual run, recorded in `NOTES.md` |
| **M2** | Decode speed on test phone (Helio G85 / SD680 class) | ≥ 8 tok/s for 0.6B | Benchmark harness (W01) |
| **M3** | Peak RSS during generation | ≤ 800MB | Benchmark harness, `VmHWM` |
| **M4** | Idle RSS 30s after last token | ≈ Compose baseline (context freed) | `adb shell dumpsys meminfo` (W08) |
| **M5** | Network capability in shipped artifact | Zero `INTERNET` permission in merged manifest | `tools/check_manifest.sh` in every build |
| **M6** | Play reviews citing "slow"/"crash"/"doesn't work" | < 5% of reviews, first 90 days | Play Console |

## 6. Scope boundaries — explicit refusals

Iteration-1 will **not** do these. Saying yes to any of them is a Spine change.

- **R1** Peer-to-peer APK sharing, off-Play distribution *(iteration-2)*
- **R2** Agent loops, tool calling, file-system access
- **R3** Model manager, model picker, multiple models
- **R4** RAG, bundled corpora, document import
- **R5** Settings screens, personas, themes
- **R6** Voice, images, multimodality
- **R7** iOS
- **R8** A "continue anyway" path on an incompatible device

## 7. Traceability anchor

`leaves/compliance/TRACEABILITY.md` is generated by `tools/trace.py`. It scans
code and tests for `spine: C<n>` tags and renders commitment → feature → test.
A commitment with no test is flagged. A feature tag with no commitment fails.

## Propagation discipline (run on every Spine change)

1. **Version + log.** Bump `spine_version`, add one changelog line: date, what, why.
2. **Architecture Leaf** — `leaves/architecture.md`. Re-walk boundaries, Build/Adopt, trust mechanisms.
3. **Engineering + Design Leaves** — `leaves/engineering.md`, `android/`, `leaves/design.md`.
4. **GTM + Compliance** — `leaves/gtm/tour.html`; regenerate `TRACEABILITY.md`.

`tools/propagate.py` lists every Leaf still stamped with an older Spine version,
in that order. A Leaf is current only when its owner re-stamps it.
